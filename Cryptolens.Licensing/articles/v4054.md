# Release notes for v4054

Version 4.0.54 improves diagnostics for built-in Web API 3 methods.

Handled transport, JSON deserialization, and other local request failures now return a non-null result with `Result = ResultType.Error` and a diagnostic `Message` instead of being converted to `null`. This is an intentional behavioral bug fix. Applications must check `Result` before treating any non-null response as successful. For compatibility across SDK versions, use:

```csharp
if (result == null || result.Result == ResultType.Error)
{
    // Do not grant access. Log or display result?.Message as appropriate.
}
```

Valid API error responses are preserved, including errors returned with a non-success HTTP status. Diagnostic messages contain the exception type and a sanitized, length-limited message; they do not append request parameters, tokens, response bodies, or stack traces.

The public low-level `HelperMethods.SendRequestToWebAPI3<T>` signature and generic contract remain unchanged. The same typed diagnostic behavior applies when `T` derives from `BasicResult` and has a public parameterless constructor; non-`BasicResult` custom contracts retain the legacy `default(T)` behavior for handled failures.

Trimming and Native AOT remain unsupported. Publishing with `PublishTrimmed` or `PublishAot` enabled now emits warning `CRYPTOLENS001`. After reviewing and accepting the risk, the warning can be suppressed with `<CryptolensSuppressTrimAotWarning>true</CryptolensSuppressTrimAotWarning>`. `PublishReadyToRun` remains supported and does not produce this warning.
